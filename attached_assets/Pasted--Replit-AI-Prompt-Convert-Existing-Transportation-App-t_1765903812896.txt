## PART 1: CONVERT EXISTING PROJECT TO MODULAR DEPLOYMENT

### Current State Analysis Required
**FIRST, analyze the existing codebase and identify:**
1. What backend APIs and services currently exist
2. What frontend interfaces are currently built
3. What SMS/notification features are implemented
4. What mobile app functionality exists (if any)
5. Current database schema and structure
6. Current deployment configuration

### Module Breakdown Strategy

Review the existing codebase and separate it into these modules:

#### **Module 1: Backend API (MANDATORY BASE)**
- Extract all backend logic, APIs, database operations
- This becomes the foundation that ALL other modules depend on
- Keep all core business logic here:
  - User authentication & authorization
  - Fleet/vehicle management APIs
  - Route management APIs
  - Dispatch operations APIs
  - Database operations
  - Core business logic
- **Deployment**: This must be deployable as a standalone API service

#### **Module 2: Frontend Web Dashboard (OPTIONAL)**
- Extract all web-based UI components
- Separate the React/Vue/Angular frontend from backend
- Create standalone web application that consumes the Backend API
- Features include: fleet management UI, dispatch dashboard, analytics, etc.
- **Deployment**: Deployable as a separate web application

#### **Module 3: SMS Capability (OPTIONAL)**
- Extract SMS/notification functionality
- Create independent SMS service module
- Connects to Backend API for data
- Handles: driver notifications, customer alerts, ETA updates, etc.
- **Deployment**: Deployable as a separate microservice

#### **Module 4: Customer White-Label Mobile App (OPTIONAL)**
- Extract or create customer-facing mobile functionality
- Booking, tracking, payments, etc.
- **Deployment**: Separate mobile app build (iOS/Android)

#### **Module 5: Admin/Driver White-Label Mobile App (OPTIONAL)**
- Extract or create driver/admin mobile functionality
- Dispatch acceptance, navigation, status updates, etc.
- **Deployment**: Separate mobile app build (iOS/Android)

**Code Refactoring Steps:**

1. **Create Module Configuration System:**
```javascript
// config/modules.js
const moduleConfig = {
  'backend-api': {
    enabled: true, // Always enabled
    mandatory: true
  },
  'frontend-web': {
    enabled: process.env.MODULE_FRONTEND === 'true',
    mandatory: false
  },
  'sms-service': {
    enabled: process.env.MODULE_SMS === 'true',
    mandatory: false
  },
  'customer-app': {
    enabled: process.env.MODULE_CUSTOMER_APP === 'true',
    mandatory: false
  },
  'admin-app': {
    enabled: process.env.MODULE_ADMIN_APP === 'true',
    mandatory: false
  }
};

// Middleware to check module access
function checkModuleAccess(moduleName) {
  return async (req, res, next) => {
    const customer = await getCustomer(req.user.customerId);
    if (!customer.enabledModules.includes(moduleName)) {
      return res.status(403).json({ 
        error: 'Module not enabled in your subscription' 
      });
    }
    next();
  };
}
```

2. **Separate Backend from Frontend:**
   - Move all frontend code to `/frontend` directory
   - Configure frontend to call backend API endpoints
   - Use environment variables for API URLs
   - Create separate build processes

3. **Extract SMS Module:**
   - Move SMS code to `/modules/sms-service`
   - Create webhook endpoints in backend
   - Make SMS service callable via API
   - Add module check before SMS operations

4. **Dockerize Each Module:**
```dockerfile
# Backend Dockerfile
FROM node:18
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]

# Frontend Dockerfile  
FROM node:18 as build
WORKDIR /app
COPY frontend/package*.json ./
RUN npm install
COPY frontend/ ./
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

5. **Create docker-compose.yml for Modular Deployment:**
```yaml
version: '3.8'
services:
  backend:
    build: ./backend
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - MODULE_FRONTEND=${MODULE_FRONTEND:-false}
      - MODULE_SMS=${MODULE_SMS:-false}
    ports:
      - "3000:3000"
    
  frontend:
    build: ./frontend
    environment:
      - API_URL=http://backend:3000
    ports:
      - "80:80"
    profiles:
      - with-frontend
    depends_on:
      - backend
  
  sms-service:
    build: ./modules/sms-service
    environment:
      - TWILIO_ACCOUNT_SID=${TWILIO_ACCOUNT_SID}
      - API_URL=http://backend:3000
    profiles:
      - with-sms
    depends_on:
      - backend
```

6. **Create Deployment Scripts:**
```bash
#!/bin/bash
# deploy.sh - Deploy only selected modules

MODULES=$1 # e.g., "backend,frontend,sms"

if [[ $MODULES == *"backend"* ]]; then
  docker-compose up -d backend
fi

if [[ $MODULES == *"frontend"* ]]; then
  docker-compose --profile with-frontend up -d frontend
fi

if [[ $MODULES == *"sms"* ]]; then
  docker-compose --profile with-sms up -d sms-service
fi
```

// components/PricingCalculator.jsx
'use client';
import { useState } from 'react';

export default function PricingCalculator() {
  const [modules, setModules] = useState({
    backend: true, // mandatory
    frontend: false,
    sms: false,
    customerApp: false,
    adminApp: false
  });

  const prices = {
    backend: 99,
    frontend: 49,
    sms: 29,
    customerApp: 79,
    adminApp: 79
  };

  const total = Object.entries(modules)
    .filter(([_, enabled]) => enabled)
    .reduce((sum, [module]) => sum + prices[module], 0);

  return (
    <div className="pricing-calculator">
      <h3>Build Your Custom Plan</h3>
      {/* Calculator UI */}
      <div className="total">
        <span>Monthly Total:</span>
        <span className="price">${total}</span>
      </div>
      <button>Start Free Trial</button>
    </div>
  );
}
